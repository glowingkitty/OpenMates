# Eleven v4 Turbo call speech

User-authorized on 2026-10-25: use Eleven v4 Turbo for call speech, retaining Voxtral transcription, Mistral manual message Speak, and ordinary automatic pre/main/post processing. Provider transport accepts incrementally released approved prose; it never waits for the final assistant response. This is an extension of the existing ElevenLabs provider, not a managed voice agent.

Multi-context v4 support is not established and is not used. `new_turn` marks dialogue prosody, not an OpenMates authorization boundary.

Example input after registering a single server-configured voice: `{"inputs":[{"text":"I found a useful example. ","voice_id":"<CURATED_VOICE>"}],"flush":true}`. Further approved text may be appended while audio is received. Example output: `{"audio":"<BASE64_MP3>"}`; `{"is_final":true}` completes normal drained input. Normalize audio to bounded bytes, optional alignment to bounded character/time arrays, and terminal events to content-free typed states. Never emit credentials, voice IDs, provider bodies, source text or audio in logs/errors.

`flush` forces generation from a short buffered phrase without ending the connection. `keep_alive` must arrive before the 20-second idle timeout. Normal end-input uses `close_socket`, which drains queued audio; interruption uses transport cancellation/close without a draining control message. A premature close, malformed/oversized event, provider error, stalled stream, lost call authority or failed publication terminates the attempt. No paid automatic reconnect or synthesis retry is allowed. Rate-limit/handshake errors yield one safe visible status and leave the canonical rich text answer intact; retry requires an explicit new authorized attempt. Existing account concurrency, call credit admission and per-append cumulative credit headroom remain required.

## Conversational delivery controls

The [current speech product guide](https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech) explicitly confirms audio tags for `eleven_v4_turbo`; the [WebSocket comparison](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/tts-vs-ttd-websockets) places expressive tags on TTD. The [prompting guide](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices) recommends punctuation and audio tags for delivery and pauses; v4 does not support SSML break tags. Delivery remains voice-dependent and should be checked with the configured voice; unit fixtures cannot prove acoustic quality.

Voice instructions may emit sparse hidden comments such as `<!-- voice:curious -->` immediately before prose. A fixed conversational allowlist (`curious`, `excited`, `thoughtful`, `whispers`, `laughs`, `short pause`) projects to the corresponding bracketed provider tags. Only comments in prose become cues; code, embeds, links and other protected rich content do not. Assistant read rendering removes these comments, including an unfinished cue during streaming, before Markdown parsing, while encrypted canonical source and raw source offsets remain unchanged. User messages and code examples retain literal content. Source hashes, safeguards, bounded input and cumulative character charging include the exact tagged text sent to the provider. Tags alone never create speech segments. Heard context reports words without delivery tags and retains the existing conservative playback semantics; audio tags provide no timing evidence.

The [pronunciation dictionary guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/pronunciation-dictionaries) explicitly supports IPA/CMU dictionary phoneme rules on v4 Turbo, including non-English. The [TTD API reference](https://elevenlabs.io/docs/api-reference/text-to-dialogue/ttd-websocket) accepts `pronunciation_dictionary_locators` only on the initial message. No pronunciation dictionaries are configured or created by this integration. The inline slash-IPA guide specifically illustrates `eleven_v4`, so inline IPA is not assumed to work on Turbo. Instructions preserve visible spelling and do not emit phonetic replacements or XML pronunciation controls.
