# Workflow authoring CLI pilot — 2026-09-29

## Tested implementation

The dev API accepts natural-language Workflow input from OpenMates CLI. One batched Jev 1.13 decision selects operation, recipe, delivery, cadence, forecast day, city, and explicit timezone. A server-owned recipe compiles a V2 graph, and executable-readiness and composition validation run before saving. Gemini 3.5 Flash-Lite writes title, description, allowed icon/category, and required free text. Gemini 3.8 Flash fills the same bounded decision contract if Jev fails or is uncertain. New workflows save disabled; schedule edits preserve enabled state; AI undo checks the saved version and later manual changes. Runtime `tomorrow` resolves in the schedule timezone. Explicit external delivery channels are rejected before model selection because a live Slack case was initially mapped to chat.

The current recipe catalog covers rain alerts, unconditional weather updates, news digests, news plus Ask AI digests, and fixed chat reminders, all on daily or weekday schedules. The editor path handles selected-workflow schedule-time changes. This is a backend/CLI pilot; the web workspace still uses its original manual-draft input.

Mean for the five create/edit requests: **7.618 s wall time** and **$0.000275 estimated inference cost**. The time includes CLI startup, authenticated API request, owner-scoped workflow encryption, Directus writes, and returned record loading. It is not just model time. The initial repeat before prompt refinement had one Jev low-confidence route that used Gemini 3.8 fallback; it still saved the correct rain graph.

An expanded 12-prompt CLI sample covered seven varied single-workflow requests, four ambiguous/unsupported requests, and one valid multi-workflow request. The seven single requests selected the expected recipe, time, timezone, and city. Three ambiguous/unsupported requests clarified correctly on the first run. A Slack delivery request incorrectly saved a chat workflow; the deterministic channel guard fixed it, and a live CLI retry returned clarification with zero model calls and zero workflow. A valid two-workflow request still clarifies because batch creation is not implemented. Thus the final behavior matches **11 of 12** intended outcomes in this small, hand-labeled sample; the missing outcome is multi-workflow creation, not a model error.

A real `workflows step-test` of the generated rain workflow completed the weather action and returned the **2026-09-30** forecast for a 2026-09-29 run in Berlin time. No scheduled workflow was activated. The generated Ask AI prompt included `{{ $nodes.news.output.results }}` and requested a three-bullet summary with sources.

## Fallback, cost, and rate observations

With Jev deliberately made unavailable inside the dev API process, Gemini 3.8 Flash plus Flash-Lite generated a valid news graph in **9.448 s / $0.000929** and a valid rain graph in **4.188 s / $0.000910** of planner time and estimated model cost. Those are real provider calls but not CLI end-to-end runs. The Jev-first path used approximately 0.3–0.6 seconds for its bounded call in the CLI sample. A four-request concurrent Jev probe had four successful responses in 0.38–0.40 seconds each and no 429; it does not establish sustained capacity.

Estimates use provider token usage, including Gemini reasoning tokens, and published paid standard inference prices as of this date: [Jev 1.13](https://openrouter.ai/typesafe/jev-1.13/api) $0.042 per million input tokens; [Gemini 3.5 Flash-Lite and 3.8 Flash](https://ai.google.dev/gemini-api/docs/pricing) $0.30/$2.50 and introductory $0.75/$3.75 per million input/output tokens respectively. Estimates exclude platform fees, workflow execution, storage, and other infrastructure. OpenRouter's [pricing page](https://openrouter.ai/pricing/) describes paid-account limits as provider passthrough and publishes no Jev-specific requests-per-second guarantee. The key metadata's `rate_limit` field is explicitly deprecated.

## Remaining before the web UI phase

The backend still needs segmentation and true all-or-none commit for multiple or mixed create/edit operations, general workflow edits and target selection from the user's overview, a validated generative topology fallback beyond the five recipes, chat preprocessing and `workflows.clarify_workflows`, and batch-aware guarded undo. Voice transcription/correction and all workspace presentation changes are also pending. An explicit unsupported-channel keyword can conservatively clarify a request that merely discusses that channel, such as news about email marketing. The pilot's small samples and four-way concurrency check do not justify a production reliability or throughput claim.
