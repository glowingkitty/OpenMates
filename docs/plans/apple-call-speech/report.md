# On-device speech for Apple voice calls

**Recommendation.** Keep the authenticated call broker and ordinary AI chat turn. Add one negotiated Apple speech mode: local Whisper in, approved speakable text out, local Supertonic 3 playback. Qualify it first in an opt-in iPhone development build. Keep cloud speech as the default on the web and on Apple devices without an eligible pair of installed models. A local call needs a connection for AI. If local speech becomes unavailable, pause and offer a clearly labeled switch to online speech for new input.

This evaluation covers the authenticated personal call path in source at `a1a738c46469b77dcc45a8c6443e7ee47d332e29`. Signed-out web has its own guest broker and anonymous allowance. No product behavior was changed.

## How calls work today

| Stage | Web | Native Apple and shared backend |
| --- | --- | --- |
| Start | The click unlocks browser audio. The app checks the saved processing acknowledgment and draft, starts mic capture and prepares the chat, then opens the authenticated call socket. The audio gate retains up to 10 seconds of startup PCM until `ready`. | Apple captures the account, server and chat scope, checks the saved acknowledgment before requesting/reserving audio, starts 16 kHz capture and prepares the canonical chat and context before sending `start`. A 10-second native deadline runs after audio reservation until valid `ready`. The broker separately allows 10 seconds for the first start frame after socket acceptance. |
| Admit and listen | `ready` activates the call, assistant speech owner and gated PCM uplink. The web detector suppresses prolonged idle upload. | The broker verifies the personal chat, session, credits and single active call, then opens the STT provider before returning `ready`. Apple validates the provider, formats, billing basis and transport, writes the encrypted lifecycle notice and flushes buffered input. Its voice-processing audio engine supplies echo cancellation and the native energy gate suppresses long quiet input. |
| Decide when to answer | Both clients receive broker transcript events. Partial text is visible while the broker holds a thinking pause. | Provider start/delta/end/resume events feed the broker. Voxtral targets a 240 ms streaming delay. At a likely end the broker checks text with a fast completion model targeting 250 ms, with a 600 ms overall model budget and a small timeout guard. Current policy specifies further silence of 0.5 s for finished/unavailable, 2 s for still thinking and 6 s for unsure. An explicit wait has no automatic submit. Resumption or material late text can revoke or revise a provisional result. An unavailable decision can release a substantive turn after the bounded silence condition. |
| Dispatch | The web passes the issued final turn to the ordinary encrypted chat sender via the shared core. | Apple binds and submits the issued final transcript through the canonical chat path. A partial carries no dispatch authority. The server runs ordinary routing, permissions, fast preprocessing, main LLM, tools and postprocessing. It delivers the canonical streamed response, including rich output, through the existing app connection. |
| Announce | Connect/disconnect sounds are local UI cues. The first response can play the neutral “starting the chat” sound/clip if the Mate is still unknown. Otherwise one prerecorded acknowledgment uses the actual routed Mate. | The backend selects fixed prerecorded acknowledgments and waiting/permission cues, with turn language, previous call language and UI language fallback where applicable. Missing language assets can mean silence. Current source generates the localized app-use line and the recap naming skills that ran as transient `voice_status` text on the call speech track. The approved spec describes the app-use announcement as prerecorded. Neither status nor acknowledgment advances the written reply's heard boundary. |
| Speak safely | The call-owned player consumes ordered MP3 chunks over the app socket. Speech overlaps generation and preserves the canonical answer and rich UI. | Eleven v4 Turbo is prewarmed per response. The server projects immutable speakable clauses. The speech safeguard has a **5-second deadline per span**. Denial or timeout blocks speech for that span and terminates the affected track. Release also requires current call authority, a durable speech claim and online TTS credit headroom. The normal chat stream continues independently. Apple admits matching call/message/segment/attempt chunks and uses the reserved audio engine. Playback completion and conservative timing determine what actually counted as heard. |
| Interrupt or end | Real recognized words can stop playback and generation before turn completion. Listener cues and echoed assistant words generally keep the turn playing. The web can resume when capture survives backgrounding and ends when the OS takes its mic. | The broker uses immediate stop/barge-in rules and bounded text intent checks. A matching interruption cancels the existing assistant task and playback, with identity fences for late events. Hangup revokes call authority, stops capture and speech and records the encrypted end notice. Ordinary saved messages and permitted ciphertext recovery survive. |

The source currently uses **Mistral Voxtral `voxtral-mini-transcribe-realtime-3-0` for live STT and ElevenLabs `eleven_v4_turbo` for generated call TTS**. This is the API baseline to preserve. The request's ElevenLabs STT assumption does not match the checked-in call route. Unrelated dictation, recording attachments and manual Speak have their own routing.

## Smallest architecture change

### One mode per device and call

- Apple checks the exact installed revision and verified files through `LocalModelStore`, the supported architecture/OS and engine, permission and audio route, and measured resource eligibility. Both Whisper and Supertonic 3 must be ready. A missing, partial, corrupt, disabled or unsupported installation uses the normal online path from the outset, under the existing saved processing acknowledgment. Keep the optional downloads and existing download flow. Enhanced PII is independent. Watch's tiny-model developer experiment is outside this path.
- Add an explicit versioned speech mode to the existing authenticated start/ready handshake. Web and legacy clients omit it. Apple treats a missing or mismatched acknowledgment as a refusal for local speech, before any upload. The server binds the negotiated mode to the active registry entry and validates the binding on every speech and AI dispatch, including continuation and reconnect. In local mode, refuse PCM, STT bias events, provider speech prewarm, provider synth and paid media jobs. Route selection in a client request alone grants no authority.
- Split the broker's input boundary where Voxtral events enter the turn state machine. The Apple audio adapter holds bounded PCM in memory and reports stable text at provisional endpoints and text revisions when needed by the existing fast completion or intent checks. Reuse the broker's turn IDs, limits, checkpoint pause, final-only issuing, de-duplication, active-call validation, waiting commands and canonical chat dispatch. Draft UI remains device-local. Existing `text_input` is a useful reference for admission and idempotency, but it finalizes and interrupts immediately and would bypass speech pause/echo policy if reused verbatim.
- On output, retain the server's stable speakable-text projection and per-span safeguard. Where the current speech sink would append approved text to ElevenLabs, publish an ordered approved span to the existing authenticated app connection, carrying call/turn/message/revision/sequence, language, selected Mate voice mapping, transient status kind and end/cancel markers. Denial, unavailable safeguard, 5-second timeout, stale authority or missing sequence never releases speech. Local synthesis consumes only that authorized stream. Keep bounded queues, monotonic sequence checks and single-turn ownership. Ordinary chat tokens are independently visible.

### Local audio, pauses and interruption

- Use existing voice-processing capture and a bounded pre-roll ring. A local speech activity detector identifies starts, resumed speech and provisional ends with hysteresis and minimum speech duration. The existing RMS gate can save idle work. It is too coarse to serve as the sole endpoint or barge-in detector. Reuse Whisper's installed tokenizer and bounded PCM runtime, extending it for rolling short windows and stable partial hypotheses. The current composer adapter accepts up to 30 seconds per batch and returns text after decoding. ASR VAD chunking alone does not make that adapter a live endpoint detector.
- Keep the last stable words when a new window overlaps, drop audio behind committed windows and keep the tail long enough to catch a trailing correction or negation. After provisional silence, reuse the bounded fast text decision for ambiguous pauses and existing wait/resume/repeat semantics. New speech invalidates old snapshots and verdicts. If the fast check misses its budget, use the current bounded silence policy; if the AI connection itself is unavailable, pause and show reconnect or end. A transcript revision or speech onset alone never submits a new turn.
- During playback, use the same echo-cancelled input and a short window of **actually played** words, including status clips, for recapture checks. Share deterministic policy in the Rust core and use stable early recognized words for a clear stop or substantive interruption. A brief backchannel stays local unless it answers a pending question or develops into a correction. Send the existing bound cancellation immediately on clear barge-in; stop local output, drop queued samples and fence late Whisper/Supertonic callbacks by generation and target identity. Use the existing bounded intent model for ambiguous text already eligible for server processing. Preserve a substantive finalized request if intent classification is unavailable. Never repeat an already committed tool action.
- Play fixed cues from a local public clip catalog keyed by allowed event, language and routed Mate. Include a small prepackaged neutral startup clip or equivalent fixed local asset. Existing short public assets can be reused where voice continuity is acceptable. Map each supported Mate to a tested stock Supertonic style and use the same local voice for regenerated Mate clips and replies where continuity is required. Never guess a Mate or substitute English for a missing locale. Use approved localized text for app-use status, skill recap and dynamic permission/wait lines that require it. Play once in order, stop on useful speech or cancellation, and never append status to history.
- Feed short synthesized clauses to the call's existing AVAudioEngine playback owner. Supertonic's CPU ONNX adapter produces whole chunks as WAV data today. Reuse the engine and add a bounded PCM output path so conversion, resampling and synthesis run off the audio callback and playback starts after the first useful clause. Keep one small lookahead, use a consistent punctuation/prosody policy and observe underruns. Mark only completed clauses heard until conservative word alignment has been qualified. Synthesis completion and queued buffers alone grant no heard progress.
- The current `LocalSpeechInferenceOwnership` allows a single owner, and the Whisper and Supertonic composer adapters hold different leases while resident. Naively warming both will either report busy or tempt a bypass of the resource guard. End-to-end testing needs one call-owned resource coordinator, coordinated with composer and lab owners. Measure serial eviction/reload and bounded alternating inference with both models resident on qualified devices. Barge-in needs enough decoder access while the player drains. Keep both resident only where physical headroom and cancellation behavior prove it safe. Low headroom can disqualify the device.

### Fallback, privacy and credits

| Situation | Behavior |
| --- | --- |
| No eligible pair at call start | Use the current API call path with its stored acknowledgment. Show the active speech mode before capture is sent. An installed pair with a temporary readiness failure should disclose online speech and require a choice before opening its mic uplink. |
| Local startup/runtime failure, OS memory warning, sustained resource pressure or serious/critical thermal state | Pause capture-to-inference, immediately fence stale results and stop queued speech. Bound and discard unsent PCM, unload after native work drains and show `Use online speech` or end. Switching closes/re-admits the broker in API mode for the same chat, with current consent and normal credits checks. Start with fresh mic capture and the next spoken turn. Never replay buffered local audio or silently switch the current response to provider TTS. The canonical reply remains readable; a later explicitly requested online replay uses existing permissions and billing. |
| Recovery, hangup or scope change | Keep encrypted committed history and normal pending write recovery. Fence workers and buffers on generation/account/server/chat change, model removal, interruption or hangup. Local reconnect re-negotiates the same mode or stops. No automatic return to local mid-call or duplicate AI dispatch. |

**Wire boundary.** “Text only” applies to the speech media plane. Send the same authorized context and final recognized text that the current call/ordinary AI paths process, plus bounded text snapshots only at the existing intent/endpoint decision boundary and the usual call control, language, IDs and receipts. Use existing scoped first-party TLS channels. Keep raw PCM, generated waveforms, uncommitted rolling hypotheses, features, voiceprints, local model inventory and debug content on device. Do not add a recording upload, server-stored speech asset, replay file, new recipient, broader context or new retention. The first slice is audio-only and sends no camera or screen data. A separately requested camera/screen session remains the existing explicit media exception when supported. Ordinary tool calls, permissions and text safeguards retain their existing recipients and scope.

**Encryption.** Capture local plaintext only where needed for live speech and ephemeral AI inference. Keep the current encrypted write/outbox, recovery receipts, client-generated keys and wrappers, and existing scoped decryption of chat context. No server plaintext storage, new plaintext column, second chat history or key export for local speech. Local audio buffers are temporary and excluded from logs and backup. AI still sees the same recognized text and approved context for inference. This is client-side encrypted history with the existing transient AI processing boundary.

**Credits.** The current call STT ledger charges accepted PCM in cumulative started minutes, at 15 credits per minute in the checked-in catalog. Call TTS uses the provider character ledger at 0.04 credits per submitted Eleven v4 Turbo character, with cumulative rounding and existing successful-work settlement. A local call opens no speech provider, accrues zero provider speech usage and skips speech-only minimum balance and TTS headroom checks. Keep normal chat/LLM/skill billing and its admission, including any existing safeguards and model usage policy. Do not change prices or free allowances. Report “On-device speech. AI usage still applies.” A user-authorized API restart bills only newly admitted cloud audio and cloud speech. For example, 75 seconds of accepted cloud PCM is 30 STT credits and 500 settled characters is 20 TTS credits. The speech component for the equivalent wholly local work is zero. This example excludes AI usage and says nothing about savings for a specific conversation.

## Marco's physical iPhone checklist

Run model-only checks with the existing lab where supported. Run full-call checks once an instrumented Apple development build offers both modes. Use the iPhone 13 Pro as the existing target and one newer iPhone for comparison. Use a separate synthetic account on dev. Record hardware, OS, app/backend commit, model revisions, call mode, audio route, battery health and charge, Low Power Mode, initial thermal state, ambient conditions and network class. Use the same Mate, locale, public inputs, volume, network and test order rotated across modes. Capture audio quality separately with consent for the fixed test material. Share numeric signposts, aggregate counts and allowlisted failure codes.

- [ ] **Baseline and capability.** On both phones start API calls with neither asset, Whisper only, Supertonic only, both verified, and a deliberately unavailable or invalid asset using a dev fixture. Compare with a web call on the same account. Confirm the initial mode, saved processing acknowledgment and ability to start when the other device has different assets. Verify the lab transcribes and synthesizes using installed models with network disabled. With networking disabled, a real call must visibly pause or fail to reach AI.
- [ ] **Cold and warm latency.** In English and German capture five cold starts after relaunch and 20 warm turns per mode per phone on stable Wi-Fi. Repeat representative warm runs on cellular. Mark user tap, permission/reservation complete, mic ready, chat/admission ready, separate Whisper and Supertonic load-ready, annotated last spoken sound, first stable ASR words, provisional endpoint, final decode, fast endpoint verdict and accepted final transcript. Then mark canonical dispatch, first main text, first safe speakable span, synthesis start, first PCM, first actual audible reply, first and last announcement audio, and playback completion. Include short and long answers. Record device-monotonic timings and correlate server-side stage durations by temporary test ID. Use an external recording or audio timing trace to calibrate audible start and barge-in stop. Report raw counts, failures, p50/p95 for warm stages, raw cold values, and gaps/underruns. Time fixed acknowledgment separately from the first substantive reply.
- [ ] **End of speech and barge-in.** On speaker and earbuds try a short question, a trailing negation, 1–3 second thinking pauses, “wait”/“warte”, resume, repeat, mic mute, sustained noise and silence. During playback use “mhm”, “genau”, an explicit “Stopp”, a correction that begins with “okay”, an intentional quote, and an answer to a pending question. Let the speaker leak a known line back into the mic. Repeat during acknowledgment, synthesis and main playback. Record false stops, false submits, clipped words, duplicates, time from first clear interrupt word to audible stop and server cancellation, and actual vs reported heard segments.
- [ ] **Announcements and safety.** In English and German start a new chat without a routed Mate, then call in an existing chat with a known Mate. Exercise tools, hold/resume and an actual approval prompt. Hear the neutral start once, the correct Mate acknowledgment once, app-use line and recap in order. Test a missing locale and an unsupported voice mapping. Use synthetic injected safeguard denial and timeout, delayed/stale spans, disconnect, account or chat switch and hangup. Verify no unauthorized or stale speech plays, no duplicate turn/tool action occurs, and the canonical text remains available when expected.
- [ ] **Memory and audio stability.** Profile physical footprint at idle, after each model load, during overlapping listen/play, during long turns, during teardown and after repeated calls. Compare serial model handoff with jointly resident models on the instrumented build. Record peak footprint, available process headroom, recovery after unload, underruns, OS warnings and termination reports. Exercise music/phone interruptions, route changes, background/lock and return, verified model removal, and an enabled Enhanced PII workflow if it can contend on that build. Force a dev memory-pressure signal to verify the transition as well as observing real device headroom.
- [ ] **Heat and battery.** Unplug at comparable charge, set fixed brightness and speaker level, and use the same network and audio route for matched 30-minute local and API calls with identical speech/idle cadence plus an idle control. Repeat in reverse order after cooling. Record battery percentage change, Instruments energy and thermal tracks, highest thermal state, time at each state, process footprint, audio stalls, applicable Low Power Mode behavior and late-call latency. Use a dev adverse thermal condition to verify the safety transition. Observe a normal sustained call separately from injected conditions. [Apple Audio System Trace](https://developer.apple.com/documentation/audiotoolbox/analyzing-audio-performance-with-instruments).
- [ ] **English and German quality.** Replay/read the same 20 public prompts per language in both modes, including quiet and noise, proper names, times, phone-like digits, amounts, German compounds and umlauts, two accents per language where practical and a code-switch. Include “How much is fifteen euros and fifty cents?”, “Ruf mich morgen um zwölf Uhr fünfzehn an” as a text-only synthetic fixture, and a corrected destination such as “Berlin, nein, Köln”. Use an account/fixture that cannot take unintended external actions. Compare word error rate and critical entity errors, and mark wrong turns separately. Blind-listen to randomized API/local pairs of the same public reply clauses. Score intelligibility, pronunciation, naturalness and voice continuity from 1–5, and record gaps, wrong language and missed clause endings.
- [ ] **Privacy, fallback and credits.** On local mode observe sanitized client/server frame-type counts and provider-request counters. Expect zero audio uploads, speech provider calls, speech jobs and speech charges, with the normal AI text request and credit entries. Inspect synthetic persisted rows for ciphertext and existing key/receipt behavior, then verify history on another authenticated device. Induce STT failure, TTS failure, memory warning, serious thermal state and loss of server capability independently. Decline online fallback once and confirm no upload; accept once and verify online requests and credits start with fresh capture. Repeat during a partly spoken reply and while the connection reconnects. Expect no leaked earlier PCM, duplicated answer, or incorrectly marked heard text.

Record each run as device/build, mode/locale/route, test case, repetitions, numeric stage timings, memory/thermal/battery readings, quality scores, interruptions/false ends/underruns, speech provider counts, credit differences and pass/fail. For a speed claim require improvement in end-of-speech to first useful audible reply on each claimed device/language, with comparable tail latency and successful runs. Qualify conversational quality against the matched API sample and document any quality or energy regression. Privacy and correct billing are hard gates regardless of speed.

## First shippable step and risks

Ship the first implementation to **opt-in dev iPhone builds** as an authenticated, foreground, personal voice-only call for English and German, with the installed pair and an explicit end-of-turn tap for the initial probe. Keep the same encrypted chat, ordinary chat billing, safety-approved speech spans, a single call player and explicit online fallback. Compare it with the online baseline on the same handsets and run the local VAD and early transcript checks in observation mode before allowing them to submit or interrupt. No production default follows from this evaluation. A user-facing rollout requires natural hands-free endpointing and interruption to pass the call contract, as well as physical-device evidence for an eligible hardware/language envelope.

The main risks are cold model load, mutually exclusive runtime leases, Whisper delay for early interruption, Supertonic clause gaps and voice mismatch, plus heat, battery and jetsam during sustained use. A mode downgrade can create a privacy breach if it flushes local PCM or opens a provider silently. Durable admission and span gating prevent forged or stale text, duplicate charges or tool runs, and unchecked playback. Supertonic's publisher archive also leaves downstream maintenance with the app. Prioritize correct routing and encrypted history first. Claim lower speech credits from zero provider use once verified, and claim faster responses only after the matched iPhone comparison.
