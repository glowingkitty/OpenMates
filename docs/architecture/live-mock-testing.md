# Cost-Safe AI Test Replay

Daily AI coverage has two explicit modes governed by
`architecture.daily-ai-test-inference@2`.

## Scheduled Replay

`TEST_LIVE_MOCK` runs local AI orchestration and replays wrapped LLM and HTTP
provider responses. Cache misses fail before provider dispatch. Legacy
`TEST_MOCK` fixtures replay cached preprocessing, response, and postprocessing
events; the worker must not run the live postprocessor afterward.

`scripts/daily_ai_test_manifest.json` is the scheduled-test policy source.
Unmarked chat-driving specs, expensive real-inference specs, and specs with
missing cache groups are excluded until they are explicitly repaired or their
cassettes are manually promoted. Run:

```bash
python3 scripts/audit_daily_ai_test_inference.py
```

## Bounded Real Canaries

One fixed and one rotating spec use `TEST_LIVE_REAL`. Both derive the same UTC
daily group and reserve conservative provider cost in Dragonfly before wrapped
LLM or HTTP dispatch. The default shared cap is EUR 0.25 and the default
LLM reservation is derived from provider pricing with a conservative UTF-8 input
token upper bound and bounded max output. Budget storage failure, exhaustion,
invalid pricing, and variable-price HTTP providers fail before dispatch and
never fall back to another provider.

These controls are ignored in production. Requests without explicit test
context retain ordinary inference behavior.

## Manual Recording

`TEST_LIVE_RECORD` never reads committed cassettes. It records into a
request-scoped candidate directory under
`/tmp/openmates-live-mock-candidates/<task-id>` by default. Save failures are
fatal. Validate and promote named groups only after the real test passes:

```bash
python3 scripts/import_live_mock_cache.py <candidate-root> --group <group> \
  --passed-real-run --passed-zero-call-replay
```

Promotion validates every JSON file before replacing canonical groups and keeps
rollback backups during the transaction. Rerun the scenario in replay mode
after promotion; a promoted cache is not accepted until that replay passes.

## Privacy Boundary

Reports may include mode, phase, provider, model, cache status, calls, tokens,
reserved cost, and normalized failures. They must not include prompts,
responses, tool payloads, cache keys, user/chat identifiers, credentials, or raw
provider errors.

## Storage Capacity Replay

The `storage_capacity_` test groups are replay-only. In nonproduction, a signed
`TEST_LIVE_MOCK` marker plus `OPENMATES_STORAGE_CAPACITY_FIXTURES=true` enables
deterministic provider outputs for recognized preprocessing, model-stream,
internal math-tool, child dispatch/completion, Project file, and compression phases. Unknown phases fail on a cache miss
before provider dispatch. The compressor's direct nonstream provider call passes
through the same replay wrapper. Record and real modes are rejected for these
groups. No fixture is generated by a paid provider.

The capacity receipt adds `blocked_provider_calls`; run-wide verification sums
every task receipt and requires zero real calls, zero misses, and at least one
replay hit. This is additional evidence to the isolated stack's internal Docker
network and absent provider credentials. The synthetic outputs measure
processing/storage behavior, not model quality or live-model latency.

`scripts/storage_capacity.py plan` emits the accepted default workload: 1000
user-days, 500 rounds, 200 embeds and 1000 versions per user, and 500
concurrent executions. The `run` command requires a real client adapter and
independent result ledger; `verify` checks exact counts, cryptographic content
digests, version reconstruction, first uncached client-ready page p95, and
aggregate replay receipts. Results from direct row seeding cannot satisfy the
operation ledger. Accelerated, burst and sustained profiles are distinct run
labels; sustained runs must be paced and report actual duration and throughput.

Example of generating a plan without contacting any service:

```bash
python3 scripts/storage_capacity.py plan --plan /tmp/storage-capacity-plan.json
```

The real client adapter in `scripts/storage_capacity_client.mjs` uses
`OpenMatesClient.sendMessage`, real client encryption, and decrypted embed
reads. It runs each disposable account in its own worker thread so CLI session
and sync state remain isolated. The client sends the replay marker through the
normal signed WebSocket field, gated to the isolated CI origin and exact replay
group. It requires disposable allowlisted account states and phase-owned
version-write and archived-page adapters; their absence aborts before writes.
One run report never declares overall capacity achieved: accelerated, burst and
sustained runs need separate evidence, including raw object-store counters.
